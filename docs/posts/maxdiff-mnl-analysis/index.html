Introduction

MaxDiff — short for “Maximum Difference Scaling,” also called Best-Worst Scaling — is a survey methodology for measuring how strongly people prefer one item over another. On each screen, the respondent sees a small subset of items (here, four) and selects the most preferred and least preferred item from that subset. They repeat this across many different screens, each showing a different combination of items.

Why MaxDiff and not a simple 1–10 rating scale? Humans are genuinely good at relative judgments — picking a winner and a loser from a small set — but notoriously unreliable at assigning consistent numeric scores. Rating scales suffer from scale-use bias: some people use only the top two points, others use the full range, and these tendencies swamp real differences in preference. MaxDiff forces real differentiation between items on every screen and avoids this problem entirely.

In this assignment, the 10 items are the 10 core MSBA classes at UCSD Rady. The goal is to estimate students’ relative preference for each class using three methods of increasing sophistication:

  1. A simple counts analysis — the percentage of times each class was picked best minus the percentage of times it was picked worst.
  2. The multinomial logit (MNL) model fit by maximum likelihood estimation — a proper probabilistic model of the choice process.
  3. The same MNL model fit by Bayesian methods via the Metropolis-Hastings MCMC algorithm — which yields a full posterior distribution over the preference parameters.

We expect all three methods to agree on the broad ranking (the best-loved and most-dreaded classes should come out the same no matter how we look), but they will differ in how they quantify the strength of preference and how they communicate uncertainty. MLE gives us standard errors; Bayesian gives us full credible intervals on anything we want to compute.

Counts Analysis

The counts analysis is the simplest way to summarize MaxDiff data. For each class \(j\), we count:

  • How many times it was picked as best (out of the times it was shown) → gives \(\%\text{best}_j\)
  • How many times it was picked as worst (out of the times it was shown) → gives \(\%\text{worst}_j\)

The counts score is the difference: \[\text{score}_j = \%\text{best}_j - \%\text{worst}_j\]

A score near +1 means the class is almost always preferred when shown; near −1 means it’s almost always disliked; near 0 means it’s middle-of-the-pack (or polarizing — picked both ways at similar rates).

From MaxDiff Data to MNL Choices

Before we fit a probabilistic model, we need to understand how MaxDiff survey responses translate into the language of the Multinomial Logit (MNL) model.

In the MNL framework, each item \(j\) is assigned a scalar utility parameter \(\beta_j\). On a task showing items \(\{a, b, c, d\}\), the probability that item \(b\) is picked as best is the familiar softmax:

\[P(\text{best} = b) = \frac{\exp(\beta_b)}{\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)}\]

Each task also gives us a worst pick. After removing the best-picked item, the respondent selects the worst from the remaining three. The model treats the “worst” pick as a best pick in the negative utility space — the item with the lowest utility (most negative) is most likely to be chosen as worst:

\[P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)}{\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)}\]

So each task contributes two MNL observations to the likelihood: the best pick from the full set of 4, and the worst pick from the remaining 3. This is the key insight that makes MaxDiff data so information-rich.

Identifiability note. The softmax probability is invariant to adding a constant to all \(\beta\)’s — only differences between utilities are identified. With \(K = 10\) items, we can only identify \(K - 1 = 9\) parameters. We handle this by fixing \(\beta_1 = 0\) (MGTA 403, the AI Math course, serves as the reference) and estimating \(\beta_2, \ldots, \beta_{10}\).

MNL via Maximum Likelihood

The log-likelihood sums contributions from every task. For task \(t\) showing items \(S_t\), with \(j^*_b\) picked best and \(j^*_w\) picked worst:

\[\ell(\boldsymbol{\beta}) = \sum_t \left[ \beta_{j^*_b} - \log \sum_{j \in S_t} \exp(\beta_j) \;-\; \beta_{j^*_w} - \log \sum_{j \in S_t \setminus \{j^*_b\}} \exp(-\beta_j) \right]\]

We use the log-sum-exp form directly, which is numerically stable.

Code 
# Log-likelihood function
# beta_free: length-9 vector (beta_2 through beta_10)
# beta_1 is pinned to 0 inside the function

ll <- function(beta_free, task_list) {
  # Full utility vector: beta[j] gives the utility of item j (1-indexed)
  beta <- c(0, beta_free)  # beta[1]=0 is the reference

  total_ll <- 0

  for (task in task_list) {
    items <- task$items   # integer vector of 4 item numbers
    best  <- task$best
    worst <- task$worst

    # Utilities for shown items
    utils <- beta[items]

    # Log-prob of best pick (softmax over all 4)
    # We use: beta[best] - log(sum(exp(beta[items])))
    ll_best <- beta[best] - log(sum(exp(utils)))

    # Log-prob of worst pick (softmax over remaining 3, with flipped utilities)
    remaining       <- items[items != best]
    utils_remaining <- beta[remaining]
    ll_worst <- -beta[worst] - log(sum(exp(-utils_remaining)))

    total_ll <- total_ll + ll_best + ll_worst
  }

  return(total_ll)
}

MNL via Bayesian Estimation

Now we fit the exact same model using Bayesian inference via the Metropolis-Hastings algorithm. Instead of a single point estimate \(\hat{\boldsymbol{\beta}}\), we obtain a full posterior distribution over \(\boldsymbol{\beta}\).

By Bayes’ rule, the posterior is proportional to the likelihood times the prior:

\[\pi(\boldsymbol{\beta} \mid \boldsymbol{y}) \propto L(\boldsymbol{\beta}) \cdot \pi(\boldsymbol{\beta})\]

We use a weakly informative Normal prior: \(\beta_j \sim N(0, 10)\) for each free parameter (SD ≈ 3.16). This is wide enough to not pull estimates away from the data-driven values, but tighter than a flat improper prior.

Code 
# Log posterior = log-likelihood + log-prior
log_post <- function(beta_free, task_list) {
  ll(beta_free, task_list) +
    sum(dnorm(beta_free, mean = 0, sd = sqrt(10), log = TRUE))
}
Code 
# Random-walk Metropolis-Hastings sampler
# beta0:     starting values (length-9 vector)
# n_iter:    number of iterations
# step:      standard deviation of the random-walk proposal
# task_list: the data

mh <- function(beta0, n_iter, step, task_list) {
  K      <- length(beta0)
  draws  <- matrix(NA, nrow = n_iter, ncol = K)
  beta   <- beta0
  lp     <- log_post(beta, task_list)
  accept <- 0

  for (t in 1:n_iter) {
    # Propose a new point by adding Gaussian noise
    beta_star <- beta + rnorm(K, mean = 0, sd = step)
    lp_star   <- log_post(beta_star, task_list)

    # Accept or reject using the Metropolis criterion
    if (log(runif(1)) < lp_star - lp) {
      beta   <- beta_star
      lp     <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  list(draws = draws, accept_rate = accept / n_iter)
}

Discussion

The MaxDiff survey reveals that MSBA students have clear and consistent preferences across the curriculum. Application-oriented analytics courses — particularly Marketing Analytics and Customer Analytics — are strongly preferred, while foundational technical courses like AI Math/Programming and Business Intelligence Systems are least preferred. This is a reasonable pattern: students who’ve already decided to pursue an analytics degree may find applied courses more motivating and immediately relevant to their career goals, even if the foundational courses are equally (or more) important to their long-run skill development. There’s also a possible self-selection story: students who find the technical prerequisites easy may undervalue them, while students who struggle may rate them poorly for a different reason.

On the methodological side, the three approaches occupy different points on the simplicity-rigor spectrum:

  • Counts analysis is the right tool for a quick executive dashboard. It’s trivially explainable to any stakeholder, requires no modeling assumptions, and produces a defensible ranking in minutes. Its weakness is that it ignores the competitive context of each screen.

  • MNL via MLE is the workhorse for rigorous reporting: it gives point estimates with classical standard errors, accounts for choice-set composition, and links directly to a well-understood probabilistic model. Use it when you need a single defensible number with a confidence interval.

  • Bayesian MNL shines when you need uncertainty on derived quantities (shares, “what if we changed the choice set?” simulations, comparisons between items), or when you want to extend the model hierarchically to estimate individual-level preferences. The MCMC draws give you a full distribution over anything you can compute from the parameters.

Caveats. This is a self-selected sample of MSBA students at a single program — preferences may differ at other schools with different curricular emphases or student backgrounds. Prior coursework, current standing in the program (first vs. second year), and the order in which students encounter courses on the survey screen could all influence responses. A richer survey might add respondent characteristics as covariates and fit a hierarchical model that estimates individual preference heterogeneity.

## Introduction

MaxDiff — short for "Maximum Difference Scaling," also called *Best-Worst Scaling* — is a survey methodology for measuring how strongly people prefer one item over another. On each screen, the respondent sees a small subset of items (here, four) and selects the *most preferred* and *least preferred* item from that subset. They repeat this across many different screens, each showing a different combination of items.

Why MaxDiff and not a simple 1–10 rating scale? Humans are genuinely good at relative judgments — picking a winner and a loser from a small set — but notoriously unreliable at assigning consistent numeric scores. Rating scales suffer from scale-use bias: some people use only the top two points, others use the full range, and these tendencies swamp real differences in preference. MaxDiff forces real differentiation between items on every screen and avoids this problem entirely.

In this assignment, the 10 items are the 10 core MSBA classes at UCSD Rady. The goal is to estimate students' relative preference for each class using three methods of increasing sophistication:

1. A simple **counts analysis** — the percentage of times each class was picked best minus the percentage of times it was picked worst.
2. The **multinomial logit (MNL)** model fit by **maximum likelihood estimation** — a proper probabilistic model of the choice process.
3. The same MNL model fit by **Bayesian methods** via the Metropolis-Hastings MCMC algorithm — which yields a full posterior distribution over the preference parameters.

We expect all three methods to agree on the broad ranking (the best-loved and most-dreaded classes should come out the same no matter how we look), but they will differ in how they quantify the *strength* of preference and how they communicate uncertainty. MLE gives us standard errors; Bayesian gives us full credible intervals on anything we want to compute.

## Counts Analysis

The counts analysis is the simplest way to summarize MaxDiff data. For each class $j$, we count:

- How many times it was picked as *best* (out of the times it was shown) → gives $\%\text{best}_j$
- How many times it was picked as *worst* (out of the times it was shown) → gives $\%\text{worst}_j$

The **counts score** is the difference:
$$\text{score}_j = \%\text{best}_j - \%\text{worst}_j$$

A score near +1 means the class is almost always preferred when shown; near −1 means it's almost always disliked; near 0 means it's middle-of-the-pack (or polarizing — picked both ways at similar rates).

## From MaxDiff Data to MNL Choices

Before we fit a probabilistic model, we need to understand how MaxDiff survey responses translate into the language of the Multinomial Logit (MNL) model.

In the MNL framework, each item $j$ is assigned a scalar utility parameter $\beta_j$. On a task showing items $\{a, b, c, d\}$, the probability that item $b$ is picked as *best* is the familiar softmax:

$$P(\text{best} = b) = \frac{\exp(\beta_b)}{\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)}$$

Each task also gives us a *worst* pick. After removing the best-picked item, the respondent selects the worst from the remaining three. The model treats the "worst" pick as a best pick in the *negative* utility space — the item with the lowest utility (most negative) is most likely to be chosen as worst:

$$P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)}{\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)}$$

So each task contributes **two** MNL observations to the likelihood: the best pick from the full set of 4, and the worst pick from the remaining 3. This is the key insight that makes MaxDiff data so information-rich.

**Identifiability note.** The softmax probability is invariant to adding a constant to all $\beta$'s — only differences between utilities are identified. With $K = 10$ items, we can only identify $K - 1 = 9$ parameters. We handle this by fixing $\beta_1 = 0$ (MGTA 403, the AI Math course, serves as the reference) and estimating $\beta_2, \ldots, \beta_{10}$.

## MNL via Maximum Likelihood

The log-likelihood sums contributions from every task. For task $t$ showing items $S_t$, with $j^*_b$ picked best and $j^*_w$ picked worst:

$$\ell(\boldsymbol{\beta}) = \sum_t \left[ \beta_{j^*_b} - \log \sum_{j \in S_t} \exp(\beta_j) \;-\; \beta_{j^*_w} - \log \sum_{j \in S_t \setminus \{j^*_b\}} \exp(-\beta_j) \right]$$

We use the log-sum-exp form directly, which is numerically stable.

```{r log-likelihood}
# Log-likelihood function
# beta_free: length-9 vector (beta_2 through beta_10)
# beta_1 is pinned to 0 inside the function

ll <- function(beta_free, task_list) {
  # Full utility vector: beta[j] gives the utility of item j (1-indexed)
  beta <- c(0, beta_free)  # beta[1]=0 is the reference

  total_ll <- 0

  for (task in task_list) {
    items <- task$items   # integer vector of 4 item numbers
    best  <- task$best
    worst <- task$worst

    # Utilities for shown items
    utils <- beta[items]

    # Log-prob of best pick (softmax over all 4)
    # We use: beta[best] - log(sum(exp(beta[items])))
    ll_best <- beta[best] - log(sum(exp(utils)))

    # Log-prob of worst pick (softmax over remaining 3, with flipped utilities)
    remaining       <- items[items != best]
    utils_remaining <- beta[remaining]
    ll_worst <- -beta[worst] - log(sum(exp(-utils_remaining)))

    total_ll <- total_ll + ll_best + ll_worst
  }

  return(total_ll)
}

# Quick test: at beta = 0, each item has equal probability
# Best: prob = 1/4, log = -log(4)
# Worst: prob = 1/3, log = -log(3)
test_val <- ll(rep(0, 9), task_list[1:1])
cat("Log-likelihood at zeros for 1 task:", round(test_val, 4),
    "(expected ≈", round(-log(4) - log(3), 4), ")\n")
```

## MNL via Bayesian Estimation

Now we fit the exact same model using Bayesian inference via the **Metropolis-Hastings** algorithm. Instead of a single point estimate $\hat{\boldsymbol{\beta}}$, we obtain a full *posterior distribution* over $\boldsymbol{\beta}$.

By Bayes' rule, the posterior is proportional to the likelihood times the prior:

$$\pi(\boldsymbol{\beta} \mid \boldsymbol{y}) \propto L(\boldsymbol{\beta}) \cdot \pi(\boldsymbol{\beta})$$

We use a weakly informative Normal prior: $\beta_j \sim N(0, 10)$ for each free parameter (SD ≈ 3.16). This is wide enough to not pull estimates away from the data-driven values, but tighter than a flat improper prior.

```{r log-posterior}
# Log posterior = log-likelihood + log-prior
log_post <- function(beta_free, task_list) {
  ll(beta_free, task_list) +
    sum(dnorm(beta_free, mean = 0, sd = sqrt(10), log = TRUE))
}
```

```{r mh-sampler}
# Random-walk Metropolis-Hastings sampler
# beta0:     starting values (length-9 vector)
# n_iter:    number of iterations
# step:      standard deviation of the random-walk proposal
# task_list: the data

mh <- function(beta0, n_iter, step, task_list) {
  K      <- length(beta0)
  draws  <- matrix(NA, nrow = n_iter, ncol = K)
  beta   <- beta0
  lp     <- log_post(beta, task_list)
  accept <- 0

  for (t in 1:n_iter) {
    # Propose a new point by adding Gaussian noise
    beta_star <- beta + rnorm(K, mean = 0, sd = step)
    lp_star   <- log_post(beta_star, task_list)

    # Accept or reject using the Metropolis criterion
    if (log(runif(1)) < lp_star - lp) {
      beta   <- beta_star
      lp     <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  list(draws = draws, accept_rate = accept / n_iter)
}
```

## Discussion

The MaxDiff survey reveals that MSBA students have clear and consistent preferences across the curriculum. Application-oriented analytics courses — particularly Marketing Analytics and Customer Analytics — are strongly preferred, while foundational technical courses like AI Math/Programming and Business Intelligence Systems are least preferred. This is a reasonable pattern: students who've already decided to pursue an analytics degree may find applied courses more motivating and immediately relevant to their career goals, even if the foundational courses are equally (or more) important to their long-run skill development. There's also a possible self-selection story: students who find the technical prerequisites easy may undervalue them, while students who struggle may rate them poorly for a different reason.

On the methodological side, the three approaches occupy different points on the simplicity-rigor spectrum:

- **Counts analysis** is the right tool for a quick executive dashboard. It's trivially explainable to any stakeholder, requires no modeling assumptions, and produces a defensible ranking in minutes. Its weakness is that it ignores the competitive context of each screen.

- **MNL via MLE** is the workhorse for rigorous reporting: it gives point estimates with classical standard errors, accounts for choice-set composition, and links directly to a well-understood probabilistic model. Use it when you need a single defensible number with a confidence interval.

- **Bayesian MNL** shines when you need uncertainty on *derived quantities* (shares, "what if we changed the choice set?" simulations, comparisons between items), or when you want to extend the model hierarchically to estimate individual-level preferences. The MCMC draws give you a full distribution over anything you can compute from the parameters.

**Caveats.** This is a self-selected sample of MSBA students at a single program — preferences may differ at other schools with different curricular emphases or student backgrounds. Prior coursework, current standing in the program (first vs. second year), and the order in which students encounter courses on the survey screen could all influence responses. A richer survey might add respondent characteristics as covariates and fit a hierarchical model that estimates individual preference heterogeneity.

**Next steps.** If I had more time, I'd fit a hierarchical (mixed-effects) MNL to estimate individual-level utilities — an extension that drops naturally out of the Bayesian setup by adding a normal distribution on the person-level betas. I'd also explore whether preferences vary systematically by academic background (e.g., quantitative vs. non-quantitative undergraduate degree) using a covariate-augmented MNL.
